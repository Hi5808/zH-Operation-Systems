# Ubuntu Touch port — Blackview BL6000 Pro (mt6873)

A **Halium-11.0** port of [Ubuntu Touch](https://ubuntu-touch.io/) (UBports) to
the Blackview BL6000 Pro 5G. This directory is the device + vendor tree plus
the build/flash tooling; it plugs into a standard Halium/LineageOS source tree.

> **Status: scaffold / bring-up.** The device tree, board config, blob list and
> tooling are complete and populated with real values extracted from the stock
> firmware dump. There is **no bootable image yet** — the next milestone is the
> first `halium-boot.img` that lights the panel. See [Roadmap](#roadmap).

---

## Why Ubuntu Touch (and not a bespoke Yocto desktop)

Ubuntu Touch is the most realistic path to a *daily-usable* Linux on this
device because it is built on **Halium**, which reuses the stock Android kernel
and the proprietary vendor HALs (GPU, camera, modem, audio) via `libhybris`.
That sidesteps the single hardest problem — there is **no mainline kernel and
no public source for the MediaTek Dimensity 800 (mt6873)**. A from-scratch
Yocto desktop would need those same blobs reverse-engineered first, with no
community device support to lean on.

The same extracted firmware (`../images`, `../artifacts`, `../configs`) feeds
either approach; this tree targets Ubuntu Touch.

## Verified hardware facts (from the dump)

| Item | Value | Source |
|---|---|---|
| SoC | MediaTek Dimensity 800 (`mt6873`), board `k6873v1_64` | bootloader/GPT |
| Kernel | `4.14.186+` arm64, **prebuilt** (no source) | `configs/kernel-4.14.186.config` |
| GPU | Mali-G57 MC4 — `mali valhall r25p0` | kernel config |
| Display | `CONFIG_DRM_PANEL_TRULY_NT36675_VDO=y` (MediaTek DRM) | kernel config |
| Touch | `CONFIG_TOUCHSCREEN_MTK_TOUCH="NT36XXX"` (Goodix GT9886) | kernel config |
| Android base | 11 (API 30), dynamic partitions, A-only | `device.mk` |
| boot header | kernel `0x40080000`, ramdisk `0x47c80000`, tags `0x4bc80000`, page `0x800` | `bootimg.cfg` |
| super | 5120 MB → system 1971 MB / vendor 592 MB / product 1885 MB | super image |

These are encoded in `BoardConfig.mk` and `device.mk`.

## Prerequisites

- A **Halium-11.0** source tree (repo-synced). See `manifests/`.
- Build host: Ubuntu 20.04/22.04, ~250 GB disk, 16 GB+ RAM.
- `fastboot`, `adb`, `e2fsprogs` (`debugfs`), and one of `unpack_bootimg` /
  `magiskboot` / `abootimg` (for `extract-kernel.sh`).
- **Unlocked bootloader** — already done on this device.

## Build workflow

```bash
# 0. Sync Halium-11.0 and drop in the local manifest
cd ~/halium-11.0
mkdir -p .repo/local_manifests
cp /path/to/manifests/blackview_BL6000Pro.xml .repo/local_manifests/
repo sync -c -j8

# 1. Extract the prebuilt kernel from the stock boot image
./device/blackview/BL6000Pro/extract-kernel.sh

# 2. Pull the vendor blobs out of the dumped vendor.img + generate makefiles
./device/blackview/BL6000Pro/extract-files.sh
./device/blackview/BL6000Pro/setup-makefiles.sh

# 3. Build halium-boot.img
./build.sh bootimage
```

`build.sh` links the device/vendor trees into `$HALIUM_SRC`, runs
`lunch lineage_BL6000Pro-userdebug`, and builds `halium-bootimage`.

---

## Flash workflow

```bash
# Put the phone in fastboot (adb reboot bootloader), then:
./flash.sh                 # halium-boot.img only (first bring-up)
./flash.sh --with-rootfs   # + Ubuntu Touch system image
```

`flash.sh` flashes a disabled `vbmeta`, then `halium-boot.img` to `boot`,
optionally the rootfs to `system` (via fastbootd), wipes userdata, and reboots.

> **Revert to stock at any time:** the bootloader is unlocked and BROM always
> answers `mtkclient`, so a full restore is possible — see
> [`../docs/BACKUP-RESTORE.md`](../docs/BACKUP-RESTORE.md).

## Notes & caveats

- **Prebuilt kernel:** we build against the stock `Image.gz-dtb`. If a
  MediaTek/Blackview GPL kernel drop is ever found, switch `BoardConfig.mk`
  from `TARGET_PREBUILT_KERNEL` to a source build for full control.
- **AVB:** disabled (`BOARD_AVB_ENABLE := false`) since the bootloader is
  unlocked. Re-enable only if you also relock (not recommended for a port).
- **Blobs:** `proprietary-files.txt` is the *minimum* set from the HAL map.
  Expect to add libs as each HAL fails to load — check `logcat`/`dmesg`.
- **Legality:** the vendor blobs are MediaTek/Blackview proprietary. Keep them
  in a private vendor repo; do not redistribute publicly.
